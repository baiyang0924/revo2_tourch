# Windows 单机调试指南

> 环境：Windows 10/11 + 灵巧手摆在桌面上 + 官方电源适配器。
> 目标：让一只手在桌面上按你的指令动起来，并能读到位置 / 电流 / 触觉反馈。
>
> **Windows 的能力边界**：只能调手，**不能联动精灵 3 整机**。
> 想联动机器人请转 `03-ELF3整机ROS2联调指南.md`。

---

## 1. 四条路径，按顺序走

| | 链路扫描 | 官方上位机（GUI） | Python SDK | 自研 Modbus 代码 |
|---|---|---|---|---|
| 工具 | `tools/rs485_probe.py` | BrainCo_RevoII_Hand_Tool | `bc-stark-sdk` | 自己写帧 |
| 适合谁 | **所有人，第一步** | 第一次上手、验证硬件 | 写脚本、做二次开发 | 需要完全掌控底层 |
| 难度 | ⭐ | ⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| 能做的事 | 只读探明端口/波特率/ID/左右手 | 手动逐指调试、读写参数、动作序列编辑 | 程序化控制、读反馈、做上层逻辑 | 任意 |
| 推荐顺序 | **第 0 步** | **第 1 步** | **第 2 步** | 需要时再做 |

**建议的推进顺序：先扫描 → 上位机跑通 → Python 脚本 → 需要时再下沉到协议层。**

> **想逐步骤照着做** → 直接看 [`08-桌面首次连线实操SOP.md`](08-桌面首次连线实操SOP.md)：
> 从"手上电、上位机已打开"一路走到"代码能控制手"，含进度表、串口↔左右手判别、
> 单位标定、串口独占的切换顺序、收尾检查表。

- **第 0 步扫描**：把"硬件通不通"和"参数填对没"两件事拆开。
  上位机里端口、波特率、ID 全靠手填，填错就报"连接失败"，
  和接错线的现象一模一样 —— 先扫描能省掉这个来回试。
- **第 1 步上位机**：用图形界面证明硬件和接线没问题，隔离变量。
- 不要一上来就写 Modbus 帧。

## 2. 路径一：官方上位机

### 2.1 准备

- 安装包：`BrainCo_RevoII_Hand_Tool_win_0635_v0.0.19`（公司文件服务器）
- 使用说明：`Revo2 上位机使用说明 V1.0`
- 驱动：`CDM-v2.12.36.20-WHQL-Certified`（USB 转串口芯片驱动，**先装驱动再插模块**）

### 2.2 硬件连接（走 485，推荐）

**连电脑调手走 485；连机器人整机才走 CANFD。**
这两个是手上**两个独立的物理接插件**，互不影响 —— 桌面这套转接盒在整机上完全用不到。

```
① 通信链路
   电脑 USB 口
      │ Type-C 线
      ▼
   BrainCo 485 转接盒（黑色铝盒，正反面丝印 BrainCo / TYPE-C / VIN / 485.0 / 485.1）
      ├── 485.0 ── A / B ──┐   A → 黄线，B → 绿线
      └── 485.1 ── A / B ──┤
                           ▼
                    手腕转接小板（CN2 左端子：黄 / 绿）
                           │ CN1 · 6 pin 排线
                           ▼
                    灵巧手手腕通信接口

② 供电链路：两处都要供，别只供一处
   独立电源 ──▶ 转接盒 VIN（黄色插头）
   独立电源 ──▶ 手腕转接小板 VCC / GND（红 / 黑）
   电源适配器 ──▶ 灵巧手 XT30 供电接口（手腕下方，12–64V）
```

**四个必须先弄清楚的点：**

1. **`485.0` / `485.1` 是两条独立总线** —— 电脑上会枚举成**两个串口**，
   不是同一根线的两个头。所以一只手占一路，两只手互不干扰。
2. **哪只手在哪个口没有规定** —— 厂商标识里没有「485.0 = 左手」这种约定，
   丝印只负责编号。**必须实测**（见 2.3）。
3. **Type-C 只走数据，不给手供电** —— 手要另接独立供电。
4. **顺序：先给手上电（绿灯常亮）→ 再插 Type-C 到电脑** ——
   手要先走完上电复位校准才会接受指令，抢跑必然超时。

> 实物照片、端子定义（黄=`485-A`、绿=`485-B`、黑=`GND`、红=`VCC`）、
> 待确认项与自检表，见 `01` 手册 **5.3 节**。
> CANFD 那一路（整机接入 / USB 转 CANFD）见 `01` 手册 5.4 节。

### 2.3 先扫描，再开上位机（第一次强烈建议）

在开上位机之前，让工具先告诉你"哪个口是哪只手、波特率和 ID 是多少"：

```bash
pip install pyserial                  # 首次需要
python tools/rs485_probe.py --list    # 看电脑识别到几个串口（应为 2 个）
python tools/rs485_probe.py           # 自动扫描，给出结论 + 可粘贴的 YAML
```

`rs485_probe.py` 是**纯只读**工具：只发功能码 `0x03` / `0x04`，
不改设备 ID、不改波特率、不触发校准、不驱动电机。
它输出每个串口上挂的是左手还是右手、实测波特率与设备 ID、固件版本与 SN。

> **为什么先扫描再开上位机？**
> 上位机会独占串口，而且里面端口 / 波特率 / ID 都要手填 —— 填错了就是"连不上"，
> 但你分不清是**填错参数**还是**硬件不通**。
> 扫描器把这两件事拆开了：**扫描能过 = 硬件链路没问题**，
> 剩下的只是在上位机里填对那几个数字。
>
> 这个顺序能省掉大量"到底是线的问题还是我填错了"的来回试。

### 2.4 上电

1. 手平放桌面，手指活动范围清空，**手不要攥任何东西**；
2. 先接好**供电线**和**通信线**：手腕转接小板 `CN1` 排线插到底、卡扣压好；
   **转接盒那端的 Type-C 先不插电脑**；
3. 打开独立电源开关（转接盒 `VIN` 同时上电）；
4. 观察：绿灯闪烁 → 手指自动张开（位置校准）→ **绿灯常亮**；
5. **绿灯常亮后**，再把 Type-C 插到电脑。

### 2.5 连接设备

1. 打开上位机；
2. **选择通信方式：`MODBUS`**（对应手上的 485 接口）；
3. 选择串口号：从 **2.3 扫描的结果**里抄，不要自己猜 ——
   `485.0` 和 `485.1` 是两个不同的 `COMx`；
4. 设置参数（同样以扫描结果为准）：

| 参数 | 出厂默认 | 怎么确认 |
|---|---|---|
| 设备 ID | 左手 `126` / 右手 `127` | `rs485_probe.py` 扫出来的 `device_id` |
| 波特率 | `460800` | 同上，扫出来的 `baud_rate` |
| 数据位 / 停止位 / 校验 | 8 / 1 / 无 | 固定值 |

5. 点连接。

**连上没连上的判断**：进 `Hand Parameters → 设备基本信息`，
**能读出固件版本号 = 链路通了**。这是最快的验证方法，
并且应该和 2.3 扫描出来的固件版本**完全一致**（不一致说明连到了另一只手）。

> ⚠️ **同一个 `COMx` 同一时刻只能被一个程序打开。**
> 上位机开着的时候 `rs485_probe.py` 会打不开串口，反之亦然。要同时用，就让两只手分居两路。

### 2.6 上位机功能页速览

| 页面 | 用途 |
|---|---|
| `Hand Parameters` | 设备基本信息、系统功能与外设（手背灯/蜂鸣器）、电机与手指参数、Turbo 功能参数、标定与恢复参数 |
| `Hand Control` | 手部整体控制（张开 / 握拳 / 内置手势） |
| `Motor` | 单电机控制：控制参数、进度条拖拽、电机状态显示 |
| `Action Sequence` | 动作序列：自定义动作、上传 / 下载 / 运行（**录制回放的前身**） |
| `Touch` | 触觉数据查看（触觉版） |

### 2.7 上手四步（别跳）

1. **读版本** —— 确认链路通；
2. **进 Motor 页，选一根手指，拖动进度条 5%，看手指是否跟随** —— 确认运动通路；
3. 加大到 30%，确认方向（值大是弯曲还是张开）；
4. 进 `Hand Control` 试内置手势（张开 / 握拳 / 捏合）。

> ⚠️ 第 2 步故意只给 5%，就是怕方向搞反把手指顶到限位。
> 第一次接触硬件时，**永远从小幅度开始**。

> **单位换算提醒**：上位机的滑块是 **0–100 百分比**，而协议层用的是**度数**。
> 两者不是线性等同的（拇指 Flex 上限 59°、Aux 90°、四指各 81°），
> 滑块 50% ≠ 协议值 50。要写代码复现上位机的动作，先对照
> `07-上位机动作编辑与代码化对照.md`。

### 2.8 连接故障快速排查

| 症状 | 排查 |
|---|---|
| 上位机里找不到串口 | ① 驱动装了吗（先装 CDM 驱动再插模块）② 换 USB 口 ③ 设备管理器里有没有带感叹号的设备 |
| 只识别出 1 个串口 | ① 另一路本来就没接 ② 驱动没装全，装完**重新插拔** ③ 换 USB 口 |
| 串口在但连不上 | ① 波特率对不对 ② A/B 接反了吗 ③ 设备 ID 对不对 ④ 手是否绿灯常亮 |
| 连上但读不到版本 | ① 通信线和供电线是否都插到底 ② 是否插错接口（485 线插到 CANFD 口上）③ 转接盒 `VIN` 有没有供电 ④ GND 是否共地 |
| 报「串口被占用 / Access denied」 | 上位机和脚本争同一个 `COMx`。关掉其中一个，或把两只手分居 `485.0` / `485.1` 两路 |
| 连上了但不是我以为的那只手 | `485.0` / `485.1` 没有规定谁是谁，读一下设备基本信息里的左右手标识，或跑 `rs485_probe.py` 确认 |
| 能读版本但手指不动 | ① 位置校准完成了吗 ② 单位模式对不对 ③ 保护电流是否被写小 |
| 一切正常，但换到另一只手上就不通 | 每只手的 ID / 端口 / 波特率可能不同，重新跑一次 `rs485_probe.py` |

> 排查时**优先用 `rs485_probe.py` 而不是反复点上位机的连接按钮**：
> 脚本会明确告诉你"端口能不能打开、有没有应答、应答的设备是哪只手"，
> 比上位机一句"连接失败"信息量大得多。

## 3. 路径二：Python SDK

### 3.1 安装

```bash
# 官方指定版本，别装最新版
pip install bc-stark-sdk==1.5.1 --index-url https://pypi.org/simple/
```

> ⚠️ 装在**系统 Python**，不要在 conda 环境里装。
> 如果 `python -c "import bc_stark_sdk"` 报找不到，先 `conda deactivate` 再试。
> 网络慢可加清华源 `-i https://pypi.tuna.tsinghua.edu.cn/simple`，但**版本仍要是 1.5.1**。

### 3.2 最小验证脚本

见 `src/revo2_standalone/01_selfcheck.py`。它做四件事：

1. 自动探测可用设备；
2. 打印设备信息与固件版本；
3. 读一次实际位置 / 速度 / 电流；
4. 用**极小幅度**让一根手指动一下，验证运动通路。

```bash
python src/revo2_standalone/01_selfcheck.py --dry-run   # 先无硬件演练，看流程
python src/revo2_standalone/01_selfcheck.py --id 126 --port COM5 --baud 460800
```

> ⚠️ **首次接真机前先跑官方 `auto_detect.py`** 确认设备与参数，
> 再核对本机 SDK 的 API 定义（`main_mod.pyi`），因为不同 SDK 版本的方法名可能有差异。
> 本仓库脚本已做方法名兜底，但**真机第一次仍建议用 `--dry-run` 先看流程**。

### 3.3 SDK 与协议的关系

```
你的 Python 代码
      │  调用
      ▼
bc-stark-sdk  ──→ 封装 Modbus-RTU 帧 + CRC16 + 串口/CAN 收发
      │
      ▼
485 / CANFD 物理层
```

也就是说：**SDK 帮你把 `04-通信协议速查` 里的帧格式和 CRC 都做好了**。
除非 SDK 不支持的场景，否则不必自己写 Modbus。

## 4. 路径三：自研 Modbus 代码（进阶）

什么时候需要：SDK 不支持你的转接器、要在嵌入式端集成、或者需要更精细的控制。

需要自己实现的部分：

| 部分 | 说明 |
|---|---|
| 串口收发 | `pyserial`，参数：115200–5M 之间（默认 460800）、8 数据位、1 停止位、无校验 |
| CRC16 | **必须自己算**（485 不像 CANFD 有硬件校验），实现见 `04` 手册第 6 节 |
| 帧编解码 | 功能码 `03H` 读保持 / `06H` 写单个 / `10H` 写多个 / `04H` 读输入 |
| 位置换算 | **位置值放大 10 倍**下发，上报也是放大 10 倍 |
| 时序控制 | 位置+时间模式，期望时间范围 1–2000 ms |

寄存器表见 `04-通信协议速查-Modbus与CANFD.md`。

## 5. 在 Windows 上开发的两个注意点

### 5.1 换行符

Windows 用 `CRLF`、Linux 用 `LF`。如果不统一，通过 Git 在两台机器间同步时
会出现「整个文件都变了」的假 diff。

**本项目已经在 `.gitattributes` 里统一为 LF**，你只要别手动改动行尾就行。
编辑器建议关掉「自动转换换行符」或设为 LF。

### 5.2 路径与中文

- 代码里尽量用**绝对路径**或 `pathlib`，避免 `\` 转义问题；
- 目录名含中文在部分工具链下会出乱码，**仓库内目录一律用英文**，
  中文只出现在 `docs/` 下的 Markdown 文件名里。

## 6. 从 Windows 到 Ubuntu 的衔接

在 Windows 上调通的东西，迁到 Ubuntu 整机时注意：

| 差异 | 处理 |
|---|---|
| 不再用 XT30 供电，改由机器人手臂线缆供 58V | 拔掉电源适配器，走 `01` 手册 4.2 节 |
| 不再用 485 转接盒，改走机器人主控板 CAN5/CAN6 | 走 `01` 手册 5.2 节 |
| 不再用上位机，改用 ROS 2 话题 | 走 `03-ELF3整机ROS2联调指南.md` |
| 端口名 `COM5` → `/dev/ttyUSB0`（独立调试时） | Linux 下需把用户加进 `dialout` 组：`sudo usermod -aG dialout $USER`，重登生效 |

> ⚠️ **迁移前必须确认一件事：桌面调试期间有没有改过设备 ID 或波特率？**
> 整机链路期望的是 **CANFD + 左 126 / 右 127**。
> 桌面如果为了实验把 ID 改成过别的值、又没改回来，装到机器人上就是"找不到手"，
> 而且现象很像硬件故障 —— 这是最容易白花半天的一个坑。
>
> 自查方法：桌面调试收尾时跑一次 `python tools/rs485_probe.py`，
> 确认扫出来的 `device_id` 仍是 126 / 127，并把结果记进 `config/hand_params.yaml`。
> 已经改了：长按手背按键 5 秒恢复出厂设置（ID 复位 126/127、485 波特率复位 460800）。
