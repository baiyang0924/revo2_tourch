# 桌面首次连线实操 SOP（Windows + 485 转接盒）

> **适用起点**：灵巧手摆在桌上、独立供电已接、485 转接盒已连电脑、
> 官方上位机（BrainCo RevoII Hand Tool）已经打开。
>
> **本文档的目标**：从"能连上"走到"能用自己的代码控制手"，
> 并且留下一份以后换电脑也能直接复用的参数台账。
>
> **配套阅读**：接线与端子定义见 [`01` §5.3](01-灵巧手硬件接线与上电操作手册.md)；
> 扫描工具用法见 [`02` §2.3](02-Windows单机调试指南.md)；
> 上位机与代码的对应关系见 [`07`](07-上位机动作编辑与代码化对照.md)。

## 1. 先回答：官方上位机还需要吗？

**需要，但它的角色会变** —— 从"唯一的操作入口"变成"标定与对照工具"。

| 阶段 | 上位机的角色 | 你主要用什么 |
|---|---|---|
| 现在（刚接线） | **主力**：可视化验证、摸清参数、试动作 | 上位机 |
| 参数摸清后（日常调试） | 备用 | 自己的 Python 脚本 |
| 需要标定 / 恢复出厂 / 编动作序列 | **不可替代** | 上位机 |

**上位机不可替代的几件事**（详见 §7）：

- 出厂参数恢复、位置校准、量程修改这类"改一次就不动"的配置；
- **动作序列编辑**（`Action Sequence` 页）——动作存在手内寄存器里，
  官方上位机是现成的编辑器，我们自己的代码目前还没实现写序列（见 `07` §7）；
- 触觉数据可视化（`Touch` 页）；
- 出问题时的"第二意见"：用来判断是**硬件坏了**还是**你代码写错了**。

**结论**：短期离不开它，长期可以只用代码，但把上位机留在电脑上当"标定/恢复/对照"工具。

## 2. 第一步：把「哪个 COM 是哪只手」钉死

### 2.1 为什么必须先钉死这件事

转接盒上 `485.0` / `485.1` 两个口**长得一样，丝印只有编号**，
厂商标识里**没有**「485.0 = 左手」这种约定 —— 谁在哪个口，取决于你怎么插。

不钉死的后果：你在上位机里给左手发指令，实际动的是右手。
**这不会报错**，只会让你怀疑"是不是动作写错了"，白绕一大圈。

### 2.2 三种判别法（从最省事到最笨，任选一种）

#### 法 A：上位机逐个连，看设备信息（最快，30 秒）

1. 上位机里选一个 `COMx`（`485.0` 或 `485.1` 对应的那个），通信方式选 `MODBUS`，
   波特率 `460800`，点连接；
2. 进 `Hand Parameters → 设备基本信息`；
3. 看 **设备 ID** 和（若有）**左右手标识**：
   - 读到 `126` → **左手**；读到 `127` → **右手**（这是出厂默认值的含义，
     判定逻辑来自 `04` §3.1 与 `rs485_probe.py` 的寄存器 `1000` / `901`）；
   - 界面里若直接写着"左/右手"，那更直接；
4. 断开，换另一个 `COMx`，重复一次 → 得到另一只手。

> ⚠️ **前提**：手上的 ID 没被人改过。
> 如果某个口上用 126 和 127 都连不上，别急着怀疑硬件 ——
> 先跳到 §4 用 `rs485_probe.py` 扫一遍，它会告诉你那个口上**实际**的设备地址是多少。

#### 法 B：只插一只手（最可靠，物理排除法）

**两路 485 是彼此独立的**，所以可以直接用"少接一路"来判定：

1. 断开其中一只手的 485 线（对应转接盒上那一路的 A/B 拔掉），另一只保持连接；
2. 上位机里刷新串口列表 —— 现在**还能连上的那个 `COMx`，就是还接着的那只手**；
3. 反过来再试一次，得到另一只。

这个方法不依赖任何寄存器数值，**只看物理连接**，缺点是要动手拔插。

#### 法 C：设备管理器插拔观察（辅助确认）

1. 打开 `设备管理器 → 端口 (COM 和 LPT)`；
2. 拔掉转接盒的 Type-C，看哪两个端口消失；
3. 插回，看它们回来 —— 这两个就是转接盒的 `485.0` / `485.1`。

> 它只能告诉你"哪两个口是转接盒的"，**分不出左右手**，要和法 A / 法 B 配合用。

### 2.3 把结果记下来（这一步别省）

填进 `config/hand_params.yaml` 的 `standalone_debug.channels`：

```yaml
standalone_debug:
  adapter:
    protocol: "MODBUS"        # 桌面上位机里选的就是它
    model: "BrainCo 485 转接模块"
  channels:
    "485.0": ""               # 填成 "COM7" 这样；写法随意，自己能看懂即可
    "485.1": ""
  left:
    port: ""                  # ← 左手所在的那个 COMx
    device_id: 126
    baud_rate: 460800
  right:
    port: ""                  # ← 右手所在的那个 COMx
    device_id: 127
    baud_rate: 460800
```

> **为什么值得记**：串口号跟着 USB 插口走，换插口或重启就会变，
> 但"转接盒的 485.0 接左手"这个**接线事实**不变。
> 记下来以后换电脑，只要认插口就行，不用重新试一遍。

## 3. 第二步：小幅度试动作 + 单位标定

### 3.1 四步，别跳（顺序不能换）

1. **读版本** —— 确认链路通（`Hand Parameters → 设备基本信息`）；
2. **`Motor` 页选一根手指，进度条拖到 5%** —— 看手指是否跟随；
3. **加大到 30%** —— 确认方向（值变大是弯曲还是张开）；
4. **`Hand Control` 页试内置手势**（张开 / 握拳 / 捏合）。

> ⚠️ 第 2 步故意只给 5%，就是怕方向搞反把手指顶到限位。
> 第一次接触硬件，**永远从小幅度开始**。

### 3.2 单位标定（一次就够，但必须做）

**上位机滑块显示的是 0–100 百分比，协议层用的是「度」。** 两者不等价：

| 关节 | 上限（度） |
|---|---|
| 拇指 Flex | 59 |
| 拇指 Aux（Ad/Ab） | 90 |
| 食指 / 中指 / 无名指 / 小指 Flex | 各 81 |

换算：`百分比 = 度数 ÷ 该关节上限 × 100`。
所以拇指 Flex 的 59° 才是 100%，而同样 100% 的拇指 Aux 实际是 90°。

**标定动作**：在 `Motor` 页选一根手指，拖到 **50%**，记下手指的**实际弯曲角度**
（目测或用量角器都行，大概到一半行程即可），再拖到 **100%** 记下终点姿态。

- 若 100% ≈ 该关节的机械极限（拇指 Flex 约 59°）→ 当前是**百分比模式**；
- 若 100% 明显超出/不足 → 到 `Hand Parameters` 里查 `_motor_data_unit_mode`
  当前的单位模式，**换模式后必须重新确认数值**。

> 标定结果写进 `config/hand_params.yaml` 的 `unit_mode` 字段，
> 并顺手把结论补进 `07` §7 的待验证清单。

## 4. 第三步：关掉上位机，用脚本独立确认

### 4.1 为什么必须做这一步

**同一个 `COMx` 同一时刻只能被一个程序打开。** 上位机开着的时候：

- `rs485_probe.py` 会打不开串口；
- 反过来，脚本跑着的时候上位机也会连不上。

在 Windows 上这个冲突的表现是 `ClearCommError failed (PermissionError(13, '拒绝访问。'))`
—— 和"硬件坏了"长得完全不一样，但如果你不知道这条，就会误判。

### 4.2 操作顺序

```
① 在上位机里点「断开连接」（不是最小化，要真正断开）
② 最好把上位机整个关掉
③ 再跑脚本
```

```bash
pip install pyserial                  # 首次需要（你本机还没装）
python tools/rs485_probe.py --list    # 应该看到 2 个串口
python tools/rs485_probe.py           # 自动扫描，给出结论 + 可粘贴的 YAML
```

**脚本会告诉你四件事**（都是只读，不改任何参数）：

| 输出 | 用途 |
|---|---|
| 每个 `COMx` 上挂的是左手还是右手 | 和 §2.2 的结论**互相验证** |
| 实测波特率与设备 ID | 填上位机和代码时用它，别猜 |
| 固件版本 | 和上位机读到的一致，说明确实是同一只手 |
| SN | 唯一标识，写进台账 |

> 扫不出来时加 `--full`（7 种波特率 × 地址 1–127 兜底），
> 能覆盖"参数被别人改过"的情况。全程只发功能码 `0x03` / `0x04`。

## 5. 第四步：让代码动起来（可以不依赖上位机）

链路确认后，按这个顺序退出上位机生态：

```bash
# ① 无硬件演练：先看流程，不碰真机
python src/revo2_standalone/01_selfcheck.py --dry-run

# ② 真机自检：读版本 → 读位置/电流 → 极小幅度动一根手指
python src/revo2_standalone/01_selfcheck.py --id 126 --port COM7 --baud 460800
```

`--id` / `--port` 用 §4 扫出来的真实值。自检脚本默认**不写任何参数**，
只有显式加 `--allow-write` 才会下发电机指令。

## 6. 桌面调试收尾检查表（每次收工前过一遍）

- [ ] 用 `python tools/rs485_probe.py` 再扫一次，
      **确认 `device_id` 仍是 126 / 127**（没被实验改过）
- [ ] 确认 485 波特率仍是 `460800`
- [ ] 确认 `config/hand_params.yaml` 里的端口 / ID / 波特率已更新为实测值
- [ ] 软件里停止动作、手指已张开、电机无堵转
- [ ] 按"软件 → 手 → 通信线"的顺序断电

> ⚠️ **桌面调试期间不要改设备 ID 和波特率。**
> 手上的 ID/波特率是"一只手套一套参数"，桌面改成别的值又忘了改回来，
> 装回机器人（走 CANFD，期望左 126 / 右 127）就会**找不到手**，
> 现象酷似硬件故障。万一手滑改了：长按手背按键 5 秒恢复出厂设置。

## 7. 上位机的不可替代场景（什么时候还得回来开它）

| 场景 | 为什么必须用上位机 | 对应页面 |
|---|---|---|
| 位置校准 / 恢复出厂参数 | 官方提供的标定流程，自己写风险高 | `Hand Parameters → 标定与恢复参数` |
| 修改单指位置量程 | 决定滑块的上下限，改错会顶限位 | `Hand Parameters → 电机与手指参数` |
| **编辑动作序列** | 动作存手内寄存器，上位机是现成编辑器；代码写序列尚未验证 | `Action Sequence` |
| 看触觉数据 | 六指触觉的原始波形，代码还没做可视化 | `Touch` |
| 排障时的"第二意见" | 上位机也连不上 → 是硬件/接线问题；上位机连得上而代码连不上 → 是代码问题 | 全部 |

> **动作序列要记得备份**：它存在**手里**，不在电脑上。
> 手返厂、固件升级、误触重置都会丢。截图只记下姿态，没记下时长与顺序。
> 用代码把序列读回来存 YAML 的做法见 `07` §2.2 / §7。
