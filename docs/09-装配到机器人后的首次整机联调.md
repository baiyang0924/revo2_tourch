# 装配到机器人后的首次整机联调

> **触发场景**：灵巧手从桌面拆下、装回精灵 3；开始要跑 ROS 2 整机联调。
> 典型困惑是「是不是必须切到 Ubuntu？可我电脑上只有 Windows」。
>
> **本文档的目标**：把「要不要装 Ubuntu」这件事讲清楚，并给出装配后第一次联调的完整步骤。
>
> 配套阅读：接线见 [`01` §4.2 / §5.2](01-灵巧手硬件接线与上电操作手册.md)，
> ROS 2 环境细节见 [`03`](03-ELF3整机ROS2联调指南.md)，
> 环境边界原理见 [`00`](00-环境边界与方案选型.md)。

---

## 0. 先把三个问题说清楚

### Q1：WorkBuddy 需要装 Ubuntu 版吗？

**不需要，而且这个概念本身不成立。**

WorkBuddy 是跑在**你这台 Windows 电脑**上的助手。ROS 2 的工作不是「让 WorkBuddy 搬到
Ubuntu 去」，而是**在另一台机器上执行命令**——那台机器就是机器人自带的机载电脑。

```
你的 Windows 电脑                     机器人机载 NUC（出厂就是 Ubuntu 22.04）
┌────────────────────┐                ┌──────────────────────────────┐
│  WorkBuddy（助手）  │  ── SSH ──▶    │  ROS 2 Humble + bxi_ros2_pkg │
│  Windows + Git Bash │                │  /canfd_packet/rx  tx        │
│  ssh / scp 客户端   │  ◀── 日志 ──   │  CAN5 → 左手126 / CAN6 → 右手127│
└────────────────────┘                └──────────────────────────────┘
```

我这台机器上已实测可用：`OpenSSH_10.3p1`、`git 2.52.0.windows.1`。
也就是说 **WorkBuddy 可以直接在 Windows 上替你跑 `ssh` / `scp` 命令去操作机器人** ——
你不需要在自己电脑上装任何 Linux。

### Q2：需要在我电脑上装 Ubuntu 双系统吗？

**不是必须的。** 分两条路，按你的目的选：

| 路线 | 你电脑需要什么 | 代码跑在哪 | 什么时候选 |
|---|---|---|---|
| **路线 ①：SSH 直连机器人** | 只要一个终端（Windows 自带 SSH） | 全部跑在机器人上 | **第一次整机联调，先走这条** |
| 路线 ②：本机装 Ubuntu 22.04 双系统 | Ubuntu + ROS 2 Humble | bridge 在机器人，commander 在你电脑 | 要长期写控制逻辑、本地看话题、本地跑仿真 |
| ~~路线 ③：Windows 装 ROS 2~~ | — | — | ❌ 不推荐，[`00`](00-环境边界与方案选型.md) 列了 5 条卡点 |

**为什么路线 ① 就能跑通**：整机联调真正需要 Linux 的原因是
**CAN 链路和厂商节点只在机器人那台机器上**。你从那台机器上跑脚本、
把结果用 SSH 看回来，一整条链路就是完整的 —— 你的笔记本扮演的只是「键盘和显示器」。

### Q3：桌面那套 485 转接盒、独立电源还用吗？

**装回机器人之后全部不用了。** 换成机器人自己的链路：

| | 桌面调试（路径 B） | 装回机器人（路径 A） |
|---|---|---|
| 通信 | 485，走 BrainCo 转接盒 | **CANFD**，走机器人手臂线缆 |
| 接口 | 转接盒 `485.0` / `485.1` → 手腕转接小板 | 左手 → 主控板 **CAN5**、右手 → **CAN6** |
| 供电 | 独立电源 + 手腕小板 `VCC`/`GND` | **手臂线缆直供 58 V**（供电+通信二合一） |
| 上位机 | Windows 官方 GUI | 不用，改用 ROS 2 话题 |

> 转接盒和手腕小板**收好留着** —— 以后要单独标定一只手、或者机器人送修时还用得上。

## 1. 装配前必做：桌面收尾（别跳过）

这是唯一能预防「装回机器人找不到手」这一步。**桌面调试期间如果改过设备 ID 或波特率，
装回机器人就会完全不通，而且现象酷似硬件故障。**

```bash
# 关掉上位机，跑一次只读扫描
python tools/rs485_probe.py
```

确认两件事并记进 `config/hand_params.yaml`：

- [ ] `device_id` 仍是 **左手 126 / 右手 127**
- [ ] RS485 波特率仍是 **460800**

若已被改过：长按手背按键 5 秒恢复出厂设置（ID 回 126/127、485 回 460800），再扫一次确认。

> 整机链路期望的是 **CANFD**，`1002` 寄存器（CANFD 波特率）应保持默认 **5 Mbps**。
> 桌面调 485 不会动到它，但如果之前手动改过，这里要一并核对。

## 2. 装配：拔什么、接什么

**拆（桌面那套）**：485 转接盒、手腕转接小板、独立电源适配器、XT30 供电线。

**接（机器人那套）**：

```
机器人躯干内 BXI 主控板
   CAN5 ──▶ 手臂走线 ──▶ 左手（ID 126）
   CAN6 ──▶ 手臂走线 ──▶ 右手（ID 127）
   （供电 58 V 与 CANFD 走同一根手臂线缆，二合一）
```

装配检查清单（动过线就过一遍）：

- [ ] 接头插到底，卡扣压好，无松动
- [ ] **左手 → CAN5，右手 → CAN6**（接反不会烧硬件，但会「一直刷数据而手指不动」）
- [ ] 差分线极性正确
- [ ] 线缆**没有被关节夹住、没有绷紧**（手臂运动时会把手拽掉线）
- [ ] **手腕法兰螺钉旋入深度 < 3 mm**（螺纹孔深 3.5 mm，超了会压裂内部电路板）
- [ ] 触觉版/进阶版**没有协议拨码开关** —— 排查清单里画掉这一项，别浪费时间拆手腕件

## 3. 让机器人能被连上

1. 机器人开机（开机后系统会自启动 `ros_elf_launch.service`）；
2. 用网线把机器人接到**和你电脑同一个交换机/路由器**上；
3. 查机器人 IP：路由器后台看设备列表，或在机器人本机跑 `ip addr`；
4. 在 Windows 上测通：

```bash
ping <机器人IP>
ssh <用户名>@<机器人IP>        # 用户名/密码问同事或主管
```

> **本机当前网段**：你电脑在 `172.16.10.48`。
> 机器人若也接在同一局域网，IP 大概率也是 `172.16.10.x`，可以直接 ping 通。
> （另外那三个 `192.168.x.1` 是虚拟机网卡，与机器人无关。）

> ⚠️ 如果 ping 不通，先确认两边在**同一网段**、机器人网口灯是否亮、
> 以及公司网络有没有做**端口隔离**（有些办公网会把同一交换机下的设备互相隔离，
> 这种情况建议让机器人直连你电脑，或找 IT 开一个不受限的口）。

## 4. 机器人侧：环境确认（照着敲）

登录机器人后，**顺序不能变**：

```bash
# ── ① 切 root（硬件节点跑在 root 下，必须一致）──
sudo su

# ── ② 在 root shell 里设环境 ──
export ROS_DOMAIN_ID=<挑对的值>          # 遥控器启动 = 30 + 机器人序号；App 启动 = 22
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export ROS_LOCALHOST_ONLY=0

# ── ③ source 顺序：先 ROS，再厂商包，最后自己的工作空间 ──
source /opt/ros/humble/setup.bash
source /opt/bxi/bxi_ros2_pkg/setup.bash

# ── ④ 确认硬件节点在（这一步过了，后面才有意义）──
ros2 topic list | grep canfd_packet
#   期望：/canfd_packet/rx   /canfd_packet/tx
```

**`ROS_DOMAIN_ID` 不确定就逐个试：**

```bash
for id in 0 22 30 31 32; do
  ROS_DOMAIN_ID=$id RMW_IMPLEMENTATION=rmw_cyclonedds_cpp ros2 topic list 2>/dev/null \
    | grep -q canfd_packet && echo "正确的是 DOMAIN_ID=$id"
done
```

> ⚠️ 最常见的写法错误：在普通用户终端设好变量再 `sudo su`。
> `sudo su` **不会继承**这些变量，**必须在 root shell 里重新 export**。

## 5. 验收：先跑官方示例，别急着跑自己的代码

**在做任何二次开发之前，先证明整条链路是通的。**

```bash
# 机器人本体启动：按遥控器 Start 键（右摇杆按下）
#   全身电机指示灯亮起，约 6 秒后自检通过
#   ★ 灵巧手自动张开 = 硬件链路正常，这一步就是最简单的验收

ros2 run bxi_revo2_example bxi_revo2_example.py
```

期望现象（官方验收标准）：手依次执行握拳/张开/单指移动 → 速度、电流、PWM 控制 →
高级控制（单位模式、位置+时间、位置+速度、多指联动）→ 内置动作序列（Open/Fist/Pinch/Point）→
设备信息查询。默认**先左手再右手**，两只都跑完且无持续报错即部署完成。

> ⚠️ 跑之前确认手指活动范围内**没有人体、线缆和易损物体**。
> 握拳行程大，第一次让机器人摆好、手朝外、人站侧面。

## 6. 跑我们仓库的脚本

### 6.1 把代码送到机器人上

**方式 A（机器人能连外网）**：在机器人上直接稀疏检出，只下自己那一块：

```bash
cd ~
git clone --filter=blob:none --no-checkout --depth 1 --single-branch \
  git@github.com:Bake-Humanoid/elf3-humanoid.git elf3-humanoid
cd elf3-humanoid
git sparse-checkout set --cone dexterous-hand
git checkout master
```

**方式 B（机器人网络差 / 不通外网）**：在 Windows 上打包再传，**排除 `.git`**：

```bash
# 在你电脑上（Git Bash）
cd /d/Desktop/机器人实习/灵巧手
tar --exclude='./elf3-humanoid/.git' -czf dexterous-hand.tar.gz \
    -C elf3-humanoid dexterous-hand

scp dexterous-hand.tar.gz <用户名>@<机器人IP>:~/

# 回到机器人的 SSH 会话里
tar -xzf ~/dexterous-hand.tar.gz -C ~/bxi_ws/
```

> 不要在 Windows 上直接改代码再拷过去 —— 换行符（CRLF/LF）和编码会出问题。
> 本仓库的 `.gitattributes` 已统一为 LF，走 Git 同步比拷 U 盘干净得多。

### 6.2 跑 bridge（必须跑在机器人上）

```bash
cd ~/bxi_ws/dexterous-hand/src/elf3_ros2

# ★ 第一步永远先跑这个：打印当前 SDK 实际暴露的符号
python3 revo2_bridge_node.py --check-api

# 左手
python3 revo2_bridge_node.py --hand left  --bus 5 --id 126 --master-id 1
# 右手（另开一个终端）
python3 revo2_bridge_node.py --hand right --bus 6 --id 127 --master-id 1
```

> **为什么 bridge 必须跑在机器人上**：它要直接占住主控板的 CAN 链路
> （`init_bxipci_device` 走的是机器人内的 PCIe 转 CANFD 硬件）。
> 换机器人、换总线、换 ID 时只改这一处。

### 6.3 发指令

**第一次联调**：直接 SSH 进机器人，在**机器人上再开一个终端**跑 commander（同一 ROS 2 域）：

```bash
python3 revo2_commander.py list                                  # 看有哪些手势/序列
python3 revo2_commander.py gesture fist --hand left --print-only # 只预览不发
python3 revo2_commander.py angles 0,0,0,0,0,0 --hand left        # 极小幅度先确认方向
```

**以后要「从自己电脑远程控制」**（这就是项目目标）：
把 commander 放到**装了 Ubuntu 22.04 的电脑**上跑（路线 ②），
两台机器在同一 `ROS_DOMAIN_ID` 下，DDS 会自动发现。

> ⚠️ 关节角顺序固定为 `[拇指Flex, 拇指Aux, 食指, 中指, 无名指, 小拇指]`，
> 上限 59° / 90° / 81° ×4。**第一次务必从小幅度开始确认方向。**

## 7. 什么时候才真的需要装 Ubuntu 双系统

不是「装到机器人上就必须装」，而是**出现下面这些需求时**才装：

| 需求 | 必须装？ |
|---|---|
| 第一次整机联调、跑官方示例、验证链路 | ❌ 不用，SSH 就够 |
| 把 bridge 跑起来、发个手势看效果 | ❌ 不用，机器人在跑 |
| 在**自己电脑上**发 ROS 2 话题远程控制机器人（项目最终目标） | ✅ **要** |
| 本地看话题 / 录 `ros2 bag` / 调试 DDS | ✅ 要 |
| 本地跑 Gazebo / MuJoCo 仿真 | ✅ 要 |
| 长期写并迭代控制逻辑 | ✅ 要 |

装的话按 [`00` §6 双系统实操要点](00-环境边界与方案选型.md)走：至少留 100 GB、
`timedatectl set-local-rtc 1` 解决 8 小时时差、NVIDIA 驱动先装再跑 Gazebo。

> ⚠️ **即使装了双系统，bridge 仍然必须跑在机器人上**（CAN 硬件在那台机器里）。
> 双系统是给自己多一个「上位控制端 + 开发机」，不是把机器人的工作搬过来。
>
> 顺便说一句：**不要在虚拟机里做整机联调** —— 无法直通 CAN 硬件、没有实时性，
> EtherCAT 基本跑不通（[`00` §7](00-环境边界与方案选型.md)）。

## 8. 装配后首次联调检查表

- [ ] 桌面收尾：`rs485_probe.py` 确认 ID 仍是 126/127、波特率 460800
- [ ] 装配：左手 CAN5 / 右手 CAN6，接插件插到底，线缆没被关节夹住
- [ ] 法兰螺钉旋入深度 < 3 mm
- [ ] 机器人上电 → 遥控器 Start → 全身自检通过 → **灵巧手自动张开**
- [ ] `ping` 通机器人，`ssh` 能登录
- [ ] root shell 里 `ROS_DOMAIN_ID` / `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp` 已设
- [ ] `ros2 topic list | grep canfd_packet` 能看到 `rx` / `tx`
- [ ] 官方示例 `bxi_revo2_example.py` 两只手都跑完
- [ ] `revo2_bridge_node.py --check-api` 能打印 SDK 符号
- [ ] 极小幅度发一条角度指令，手指跟且方向正确
- [ ] 把确认到的真实参数（DOMAIN_ID、总线、ID、固件版本）记进 `config/hand_params.yaml`

## 9. 出问题

按顺序查：

1. `/canfd_packet/rx` `tx` 在不在 → 不在是硬件节点没起（[`05` §5.1](05-故障排查手册.md)）
2. `ROS_DOMAIN_ID` 是否一致 —— **整机排名第一的坑**
3. 左右手是否接反（症状：终端刷数据但手指不动）
4. 有没有别的进程在抢同一只手（`ros2 node list` / `ps aux | grep -i revo`）
5. 完整分层排查见 [`05-故障排查手册.md`](05-故障排查手册.md)
