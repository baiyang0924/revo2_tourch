# 18 · 真机灵巧手控制与手势库

> 背景：Revo2 灵巧手装配到 ELF3 本体后，需经机器人机载电脑控制。
> 本文记录控制链路的打通、控制接口、位置标定方法与手势库。
> 全部结论均为真机实测（2026-09-24，右手 / `SkuType.MediumRight`）。

---

## 0. 结论摘要

| 项 | 结果 |
|---|---|
| 控制链路 | 上位机 → SSH → 机器人机载电脑 → BXI 主控板 CANFD → 灵巧手 |
| 手的访问前提 | 控制程序**必须运行在机器人上**（手的通信经 BXI 主控板，该硬件不在上位机） |
| 运行身份 | **root**，且 `ROS_DOMAIN_ID` / `RMW_IMPLEMENTATION` / `CYCLONEDDS_URI` 须与硬件节点一致 |
| 位置量程 | `Normalized` 模式，**0 ~ 1000**（0 = 完全伸直，1000 = 完全弯曲） |
| 下发方式 | 默认速度即最快（全行程 **0.69 s**）；显式指定 `max_speed` 反而慢 6 倍且不到位 |
| 姿态来源 | 内置手势库与触觉接口在本机不可用 → 姿态由 MuJoCo 手模型数值优化标定 |
| 手势库 | 13 段，整场约 55 s，实测到位 |
| 上位机要求 | Windows / Linux 均可（Windows 需 OpenSSH，10/11 自带） |

## 1. 控制链路

```
上位机（Windows 或 Linux）
   │  SSH
   ▼
机器人机载电脑  bxi@172.16.10.47
   │  ROS 2 → /canfd_packet/rx|tx
   ▼
BXI 主控板（PCI 设备：Xilinx 7022）
   │  CANFD  左 CAN5 / ID 126 ，右 CAN6 / ID 127
   ▼
Revo2 灵巧手
```

**为何控制程序不能运行在上位机**：示例通过 `init_bxipci_device()` 访问 BXI 主控板，
而上位机不存在该 PCI 设备（`lspci` 无匹配项）。

**上位机侧只需具备 SSH 客户端**，不需要 ROS 2、不需要 CAN 接口。

---

## 2. 运行环境（两个必踩的坑）

### 2.1 必须与硬件节点对齐 ROS 环境

硬件节点以 **root** 身份运行，并使用固定的 ROS 域与 CycloneDDS 配置。
未对齐时，程序会打印「桥接初始化成功」，但**灵巧手无应答**：

```
RuntimeError: No response from slave
```

**配置值只能从运行中的进程读取**，不能照抄文档：

```bash
sudo bash -c 'for p in $(pgrep -f "ros_bridge_node|bxi_rc_ros2_start"); do
  tr "\0" "\n" < /proc/$p/environ | grep -E "ROS_DOMAIN|RMW|CYCLONEDDS"; done'
```

本机实测值：

```
ROS_DOMAIN_ID=22
RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
ROS_LOCALHOST_ONLY=0
CYCLONEDDS_URI=<CycloneDDS><Domain Id="any"><General><Interfaces>
  <NetworkInterface name="lo" multicast="true"/></Interfaces>
  <AllowMulticast>true</AllowMulticast></General></Domain></CycloneDDS>
```

### 2.2 `CYCLONEDDS_URI` 标签大小写

结尾标签须与开标签一致（`</CycloneDDS>`）。写成小写会导致：

```
//CycloneDDS: parser error open/close tag mismatch (Clonedds)
→ rmw_create_node: failed to create domain
```

**该故障不报错、只让 `ros2 topic list` 返回空列表**——若 stderr 被重定向，
现象就只剩「机器人上什么都没有」，极易误判。**调试 ROS 环境时不应屏蔽 stderr。**

修正后话题总数由 2 增至 54，`/canfd_packet/rx`、`/canfd_packet/tx` 出现。

### 2.3 运行封装

`tools/revo2_hand_run.sh` 固化以上环境（须在 root 下 source）：

```bash
sudo bash /home/bxi/run.sh <脚本.py> [参数...]
```

## 3. 控制接口

```python
from bxi_can_node import (init_bxipci_device, cleanup_bxipci_device,
                          libstark, stop_bxipci_runtime)

# 建立连接（右：bus=6 / slave=127；左：bus=5 / slave=126；master_id=1）
ctx = await init_bxipci_device(6, 127, master_id=1, is_canfd=True,
                               hw_type=libstark.StarkHardwareType.Revo2Basic)

info = await ctx.handle.get_device_info(ctx.slave_id)      # 型号 / 固件 / SN
st   = await ctx.handle.get_motor_status(ctx.slave_id)     # 位置 / 电流 / 状态

await ctx.handle.set_finger_positions(ctx.slave_id, [0, 0, 0, 0, 0, 0])
await cleanup_bxipci_device(ctx)
```

**下发数组顺序**（单指微动实测确认）：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 关节 | 拇指屈曲 | 拇指对掌 | 食指 | 中指 | 无名指 | 小指 |
| `FingerId` | `Thumb` | `ThumbAux` | `Index` | `Middle` | `Ring` | `Pinky` |

**位置量程**：`Normalized` 模式 0~1000，与实读值 1:1。
换算关系 `值 = 角度 / 该关节行程上限 × 1000`，行程上限见 §4。

## 5. 姿态标定方法

### 5.1 内置手势与触觉在本机不可用

- `run_action_sequence(DefaultGesture*)`：各手势实读值几乎相同、四指全为 0，
  内置手势未生效（判定采用「连续两次读数一致」的稳定判据，非固定延时采样）
- 触觉接口全部返回 `Operation requires Tactile sensor device`

因此「指尖相触」一类姿态需自行标定。

### 5.2 MuJoCo 数值优化标定

工具：`tools/revo2_hand_ok_calib.py`

1. 目标函数 = 拇指指尖与目标手指指尖的距离（`mj_forward` 后读 `d.xpos[id]`）
2. 变量 = 拇指对掌 + 拇指屈曲 + 目标手指 proximal
3. 不参与的手指锁定为 0（保持伸直）
4. 粗搜 40000 次随机 + 坐标下降细化
5. 换算：`sdk值 = 关节弧度 / 该关节行程上限 × 1000`

标定结果（OK 手势，源自 `config/revo2_ok_gesture.json`）：

| OK 手势 | 下发值 | 仿真指尖距 |
|---|---|---|
| 拇指+食指 | `[821, 801, 777, 0, 0, 0]` | 0.0 mm |
| 拇指+中指 | `[646, 983, 0, 908, 0, 0]` | 0.0 mm |
| 拇指+无名指 | `[716, 1000, 0, 0, 867, 0]` | 9.5 mm |
| 拇指+小指 | `[893, 1000, 0, 0, 0, 745]` | 22.9 mm |

> 拇指与小指的最短距离受解剖限制，无法完全接触。

**输出顺序注意**：模型侧关节名以 `metacarpal`(对掌) 在前，而 SDK 数组以
`proximal`(屈曲) 在前，顺序写反会导致拇指两关节互换。

### 5.3 真机复核：拇指「被挡住」而非「行程不足」

OK 手势下发值与实读值存在差异（下发 821/801 → 实读 687/703）。
单独测试显示拇指行程充足（见 §4），且拇指对掌实读值随目标手指外移而递增
（703 → 728 → 761 → 761，对应食指 → 中指 → 无名指 → 小指），
说明**差异源于与目标手指的物理接触**。

**段子寻址**：`--only` 接受名称或**编号**。编号形式用于批处理脚本——
Windows `cmd` 为 GBK 而远端为 UTF-8，中文名称经命令行传递会乱码。

## 7. 相对时序的写法

「后一根手指在前一根到达 50% 行程时启动」等价于固定时间偏移：

```
第 k 根手指启动于 k × 0.5T  （T = 单指运动时长）
→ 单阶段总时长 = (n-1) × 0.5T + T
```

实现为进度函数 `p_k = clamp((t - k·0.5T)/T, 0, 1)`，
`pos = from + (to - from) × p_k`；交换 `from` / `to` 即可复用于反向。

**真机注意**：「指令下发完成」不等于「动作完成」，手对目标位置存在跟随延迟。
阶段结束后需留 0.5~0.8 s 收敛时间再读位置或进入下一阶段；
首次标定时曾因立即读数而得到中间值（应为 0 的位置读到 207）。
