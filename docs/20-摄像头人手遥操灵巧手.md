# 20 · 摄像头人手遥操灵巧手（视觉数据手套）

> 用电脑摄像头识别操作者的手，把姿态实时复现到机器人的灵巧手上。
> 相比预录手势库，遥操可以做出任意手势，演示与示教都更灵活。

---

## 0. 结论摘要

| 项 | 结果 |
|---|---|
| 实现方式 | 摄像头 → MediaPipe 手部关键点 → 6 个电机值 → TCP → 机器人 → 灵巧手 |
| 识别频率 | 摄像头 30 fps，下发约 20 Hz |
| 跟随延迟 | 约 0.1 ~ 0.3 s |
| 状态 | 已跑通，四指跟随准确；拇指为近似映射，精度有限 |

---

## 1. 架构

```
Windows 本机                                     机器人（机载电脑）
┌──────────────┐                            ┌──────────────────┐
│ 摄像头       │                            │ TCP 服务端(root) │
│   ↓          │                            │   ↓ 校验         │
│ MediaPipe    │    TCP 9910, 约 20 Hz      │ SDK 下发         │
│ 21 关键点    │ ─────────────────────────→ │   ↓              │
│   ↓ 映射     │                            │ CANFD → 灵巧手   │
│ 6 个电机值   │                            └──────────────────┘
└──────────────┘
```

**为何不走 ROS**：本机通常没有 ROS 2 环境，而本机与机器人在同一网段，
直接用 TCP 更省事，也避开了 DDS 跨网段 / 环境变量对齐的问题（见 `docs/18` §2）。

### ⚠️ MediaPipe 1.0 的 API 变更

1.0 版本**移除了旧的 `mp.solutions.hands` 接口**，必须改用新的 Tasks API：

```python
from mediapipe.tasks.python import BaseOptions, vision
opts = vision.HandLandmarkerOptions(
    base_options=BaseOptions(model_asset_path="hand_landmarker.task"),
    running_mode=vision.RunningMode.VIDEO,      # 视频模式，需传时间戳
    num_hands=1)
landmarker = vision.HandLandmarker.create_from_options(opts)
```

而且**模型不随包安装**，需单独下载（约 7.8 MB）：

```
https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task
```

VIDEO 模式下 `detect_for_video()` 的时间戳必须单调递增，否则检测会失败。

## 3. 部署与运行

### 机器人端（接收服务）

```bash
sudo bash /home/bxi/run.sh /home/bxi/hand_teleop_server.py --hand right
```

监听 `0.0.0.0:9910`，收到一行 `v1,...,v6`（每个 0~1000）后校验并下发。

服务端职责：
- 越界值直接拒绝并回送 `ERR`
- 限流 `MIN_GAP = 0.045 s`（约 22 Hz），避免刷屏占满总线
- 空闲超过 1.5 s 停止下发，把手交回底层控制

### 本机端

```powershell
python D:\sim\hand_teleop_client.py
```

或双击 `teleop.bat`（会自动在机器人上起接收服务，再开本机识别窗口）。

**操作键**：`q` 退出　`+` / `-` 调灵敏度

## 4. 姿态映射算法

核心思路：**用比值而不是绝对距离**，这样手离摄像头远近不会影响结果。

### 四指（食指 / 中指 / 无名指 / 小指）

```
骨长   = |MCP→PIP| + |PIP→DIP| + |DIP→TIP|
直线距 = |MCP→TIP|
比值   = 直线距 / 骨长          # 伸直≈0.95，完全弯曲≈0.40
curl   = (1 - 比值) / 0.55      # 归一到 0~1
```

### 拇指（两个自由度）

- **屈曲**：同四指算法（拇指只有 CMC / MCP / IP / TIP 四个点，为近似）
- **对掌**：`|拇指尖→食指根| / 手掌尺寸`，再按经验区间归一

**拇指是简化映射**：真人拇指有鞍状关节、自由度远高于 2 个电机，视觉上尤其"横向摆动"难用单一标量表达，因此跟随精度明显低于四指。

### 平滑

识别结果用指数平滑（`alpha = 0.45`）后再下发，抑制关键点抖动。

## 5. 已知限制

| 问题 | 原因 | 现状 |
|---|---|---|
| **拇指不准** | 拇指自由度高，2 个电机难以表达；对掌角视觉估计误差大 | 近似可用，需按现场手感调经验系数 |
| **只跟随先被检测到的手** | `num_hands=1`，MediaPipe 返回第一只手，不区分左右 | 尚未支持指定左右手 |
| **突然停止跟随** | 疑似灵巧手电机持续受力后过热保护 | 已观察到，待进一步确认与处理 |

### ⚠️ 操作禁忌：不要与其它手控脚本同时运行

灵巧手的 SDK **不支持两个客户端同时持有同一只手**。遥操服务运行期间若再用其它脚本（如 `hand_fist.py`、读位置脚本）连接同一只手，会**抢走控制权**，导致遥操下发静默失败——表现为"识别正常、连接正常，但手不动"。

排查此类问题时，**应先确认没有其它进程占用手**。

---

## 6. 排查清单

| 现象 | 检查 |
|---|---|
| 识别窗口无关键点 | 摄像头编号是否正确（`--cam`）；光线是否充足 |
| 连不上机器人 | 先 `ping` 机器人；确认服务端已启动（`ss -tln \| grep 9910`） |
| 有画面有数值但手不动 | **是否有其它脚本占用手**；服务端窗口是否打印 `ERR 下发失败` |
| 跟随幅度偏小 | 按 `+` 提高灵敏度；或做一次张开 / 握拳标定 |
| 手发热后停止响应 | 暂停使用使其冷却；确认是否为过热保护 |
