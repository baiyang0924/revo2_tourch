## 1. 登录机器人

### 1.1 主机名与账号

机器人机载电脑出厂主机名形如 `elf3-82`，支持 mDNS：

```bash
ssh bxi@elf3-82.local
```

| 项目 | 值 |
|---|---|
| 用户名 | `bxi` |
| 主机名 | `elf3-82.local`（实际编号以现场为准） |
| 密码 | **见内部凭据管理 / 问主管，不要写进仓库** |
| 系统 | Ubuntu 22.04 + ROS 2 Humble（机载，出厂预装） |

> 🔐 明文口令**不落在本仓库**：仓库再怎么私有，凭据一旦提交就很难彻底清除。
> 需要时请向主管或负责同事索取。

### 1.2 `xxx.local` 连不上怎么办

按这个顺序试：

```bash
# ① 先看能不能解析
ping elf3-82.local

# ② 解析不了就找 IP：看路由器后台的 DHCP 列表，或在 Windows 上
arp -a | findstr 172.16.10

# ③ 拿到 IP 直接连
ssh bxi@172.16.10.xx
```

前提：**你的电脑和机器人在同一个网段**（同一台交换机 / 同一个 Wi-Fi）。
本机 Windows 侧当前地址是 `172.16.10.48`，机器人大概率也在 `172.16.10.x`。

### 1.3 传文件

```bash
# 上传整个工作空间（第一次同步用，之后改单个文件即可）
scp -r ~/elf3_ws/bxi_rl_controller_ros2_example bxi@elf3-82.local:/home/bxi/bxi_ws/

# 只传一个文件
scp src/bxi_example_py_elf3/mods/com.bxi.basic_actions/xxx.py \
    bxi@elf3-82.local:/home/bxi/bxi_ws/bxi_rl_controller_ros2_example/src/.../

# 从机器人往回拉（机器上的东西比自己下的快，见 docs/10 路线 A）
scp -r bxi@elf3-82.local:/opt/bxi/bxi_ros2_pkg /opt/bxi/
```

## 2. 机器人侧环境（最容易踩坑的一节）

### 2.1 硬件节点必须用 root 跑

官方明确要求：**真机侧用 `root` 用户**。所以每次开终端都是这个顺序：

```bash
ssh bxi@elf3-82.local
sudo -i                                   # 切 root
source /opt/ros/humble/setup.bash
source /opt/bxi/bxi_ros2_pkg/setup.bash
source /home/bxi/bxi_ws/bxi_rl_controller_ros2_example/install/setup.bash
```

三条 `source` **顺序不能换**，后一条依赖前一条。

### 2.2 ⚠️ `ROS_DOMAIN_ID` 是整机第一大坑

机器人的硬件节点在 root 下运行，**它在哪个 Domain，你就必须在哪个 Domain**，
否则两边"各自都在跑、但互相看不见"——现象是话题列表空的、动作没反应，
非常像硬件坏了。

```bash
# 在 root shell 里（不要只在普通用户里 export 再 sudo su，见下）
export ROS_DOMAIN_ID=<机器人的DOMAIN_ID>
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export ROS_LOCALHOST_ONLY=0
export CYCLONEDDS_URI='<CycloneDDS><Domain Id="any"><General><Interfaces><NetworkInterface name="lo" multicast="true"/></Interfaces><AllowMulticast>true</AllowMulticast></General></Domain></CycloneDDS>'
```

> **`sudo su` 不会自动继承**你普通用户终端里的所有 ROS 环境变量。
> 正确的做法是**先 `sudo -i` 进 root，再在 root shell 里 `export`**，
> 并且**在同一个 shell 里**启动你的程序。

`ROS_DOMAIN_ID` 具体是几：问主管或看机器人上的服务配置
（`/etc/systemd/system/ros_elf_launch.service` 里能看到它给节点设了什么）。

### 2.3 环境自检三条命令

```bash
# ① 有没有消息包（没有就是 bxi_ros2_pkg 没 source 对）
ros2 interface show communication/msg/MotionCommands

# ② 灵巧手走的那两条话题在不在（在 = 硬件节点起来了）
ros2 topic list | grep canfd_packet      # 应看到 /canfd_packet/rx 和 /canfd_packet/tx

# ③ 整机话题前缀：真机是 hardware/，仿真是 simulation/
ros2 topic list | grep -E "^/hardware|^/simulation" | head
```

## 3. 启动 / 重启机器人程序

### 3.1 服务方式（现场常用）

机器人出厂把启动做成了 systemd 服务：

```bash
sudo systemctl status  ros_elf_launch.service    # 看状态
sudo systemctl restart ros_elf_launch.service    # 改完代码后重启
sudo systemctl stop    ros_elf_launch.service    # 停
sudo journalctl -u ros_elf_launch.service -f     # 跟日志（排障必用）
```

> 这个服务文件在仓库的 `script/ros_elf_launch.service`，
> 装的时候是 `cp` 到 `/etc/systemd/system/` 再 `enable`。
> **改了服务里写的路径或环境变量，要 `sudo systemctl daemon-reload` 才生效。**

### 3.2 手动方式（调试时用，能直接看到输出）

```bash
cd /home/bxi/bxi_ws/bxi_rl_controller_ros2_example
# （先做第 2.1 节的三条 source）
ros2 launch bxi_example_py_elf3 example_demo_hw.launch.py
```

> 📌 **launch 文件名有两个版本在流传**：
> 有的人记录写 `example_demo_hw.launch.py`，官方 README 写 `example_launch_demo_hw.py`。
> **别猜，先列一下再说**：
> ```bash
> ls src/bxi_example_py_elf3/launch/
> ```
>
> 另外硬件 launch 支持传参：
> `robot_config_file:=/opt/bxi/robot_config.yaml`、`enable_head:=auto|true|false`。

## 4. 真机动作指令（`motion_commands`）

### 4.1 动作 → 按键字段对照表

真机动作全部通过往 `/motion_commands` 发一条 `MotionCommands` 消息触发。
**同一时刻只置一个 `btn_*`，其余全为 0。**

| 动作 | 字段 | 值 | 备注 |
|---|---|---|---|
| **零位模式** | `btn_4` | `1` | 各关节回零位 |
| **初始姿态** | `btn_3` | `1` | 站好，后续动作的前提 |
| **normal 走路** | `btn_1` | `1` | 常规步态 |
| **cheer（欢呼）** | `btn_10` | `7` | 与仿真键盘 `7` 对应 |
| **单臂碰拳** | `btn_10` | `9` | |
| **双臂叉腰** | `btn_10` | `10` | |
| **双臂拥抱** | `btn_10` | `11` | |

> 遥控器还有行走/奔跑/起身等按键，**`btn_2` 起身、`btn_5`/`btn_6` 变速**等
> 需要对着 `src/remote_controller/config/xbox_default.yaml` 核一遍再发，
> 别照着仿真键盘表想当然。

### 4.2 用工具发（推荐，不用手抄那一长串 JSON）

手抄 `MotionCommands` 的完整 JSON 有 **10 个 `btn_` + 10 个 `axis_`**，
极易抄错一个字段而完全不报错。所以配了个小工具：

```bash
# 看有哪些动作
./tools/elf3_cmd.sh --list

# 只看会发什么，不发（真机第一次务必先 dry-run）
./tools/elf3_cmd.sh stand --dry-run

# 真发
./tools/elf3_cmd.sh stand
./tools/elf3_cmd.sh walk
./tools/elf3_cmd.sh cheer
```

### 4.3 原始命令（工具出问题时的手工兜底）

```bash
ros2 topic pub /motion_commands communication/msg/MotionCommands \
"{header: {stamp: {sec: 0, nanosec: 0}, frame_id: ''}, vel_des: {x: 0.0, y: 0.0, z: 0.0}, height_des: 0.0, yawdot_des: 0.0, mode: 0, btn_1: 0, btn_2: 0, btn_3: 1, btn_4: 0, btn_5: 0, btn_6: 0, btn_7: 0, btn_8: 0, btn_9: 0, btn_10: 0, axis_1: 0, axis_2: 0, axis_3: 0, axis_4: 0, axis_5: 0, axis_6: 0, axis_7: 0, axis_8: 0, axis_9: 0, axis_10: 0}" --once
```

（上面这条是「初始姿态」：`btn_3: 1`，其余全 0。）

## 5. 仿真环境（不接机器人也能练）

### 5.1 启动

```bash
# 终端 1：仿真器 + 控制策略
source ~/elf3_env.sh
ros2 launch bxi_example_py_elf3 example_launch_demo.py

# 终端 2：键盘控制（鼠标点一下这个窗口保持焦点）
source ~/elf3_env.sh
ros2 launch remote_controller remote_controller_keyboard.launch.py
```

`~/elf3_env.sh` 就是三条 `source` 打包（内容见 `docs/reference/` 里那份装机方案）。

### 5.2 键盘速查

| 按键 | 动作 | 按键 | 动作 |
|---|---|---|---|
| `1` | 站立 / 行走模式 | `5` | 中速奔跑 2 m/s |
| `W`/`S` | 前进 / 后退 | `6` | 后空翻（官方未发布，无反应属正常） |
| `A`/`D` | 左移 / 右移 | `7` | 前空翻 |
| `Q`/`E` | 左转 / 右转 | `8` | 鼓掌 |
| `空格` | 停止 | `9` | 打招呼（挥手） |
| `2` | 起身（摔倒后爬起） | `0` | 深度相机行走 |
| `3` | 跳舞 | `Shift+1` | PD 刹车回初始姿态 |
| `4` | 高速奔跑 4 m/s | `Tab` | 切换相机视角 |

### 5.3 仿真/真机的四条差异（官方说明）

1. **`hw` = `hardware`**。所有带 `hw` 的 launch 都会**启动真实硬件**，在开发机上千万别手滑。
2. 仿真话题带 `simulation/` 前缀，真机带 `hardware/` 前缀。
3. 仿真里机器人启动时**带虚拟悬挂**，启动后需要释放；真机忽略悬挂信号。
4. 仿真有全局里程计话题 `odm`，真机没有。

## 6. 把改好的动作代码部署上去

### 路线 1 · 官方预设注入脚本（推荐，配合动作生成工具用）

```bash
python3 apply_presets_to_bxiws.py \
  --src-dir ~/下载 \
  --mod     ~/elf3_ws/bxi_rl_controller_ros2_example/src/bxi_example_py_elf3/mods/com.bxi.basic_actions \
  --config  ~/elf3_ws/bxi_rl_controller_ros2_example/src/remote_controller/config/xbox_default.yaml

cd ~/elf3_ws/bxi_rl_controller_ros2_example
colcon build --packages-select bxi_example_py_elf3 remote_controller --symlink-install
source install/setup.bash
```

### 路线 2 · 整包同步到机器人

```bash
# ① 本地 → 机器人
scp -r ~/elf3_ws/bxi_rl_controller_ros2_example bxi@elf3-82.local:/home/bxi/bxi_ws/

# ② 登录机器人编译
ssh bxi@elf3-82.local
cd /home/bxi/bxi_ws/bxi_rl_controller_ros2_example
source /opt/ros/humble/setup.bash
source /opt/bxi/bxi_ros2_pkg/setup.bash
bash build.sh

# ③ 重启服务让新代码生效
sudo systemctl restart ros_elf_launch.service
```

```bash
colcon build --merge-install --packages-select bxi_example_py_elf3 remote_controller
```

## 7. 校准类命令

### 7.1 头部电机零位漂移

```bash
sudo /opt/bxi/bxi_ros2_pkg/lib/hardware_elf3/hw_lib_test_elf3
# 进去后输入：
mit_zero_set_single 29
```

换第二个电机就把 `29` 换成对应编号（现场记录里用过 `29` 和 `30`）：

```bash
sudo /opt/bxi/bxi_ros2_pkg/lib/hardware_elf3/hw_lib_test_elf3
mit_zero_set_single 30
```

> ⚠️ 这是**写零位**的操作，会改变硬件标定。动手前确认：机器人处于
> 安全姿态、周围无人、急停在手边，并且知道怎么改回去。

## 8. 红线清单

1. **绝对不要在仿真开发机上运行任何带 `hw` 的 launch 文件** —— 那是驱动真实硬件的。
2. **失控保护 100 ms**：控制命令断流超过 100 ms，保护触发，**电机会失能**，
   必须重新初始化才能继续。所以不要在动作执行中切窗口、断 SSH。
3. **启动是两步**：第一次 `reset` 让关节转到零位并保持 10 秒，
   第二次 `reset` 才开始接收控制输入。跳过任何一步都会觉得"发指令没反应"。
4. **硬件保护计数器**：速度超限 +50、力矩超限 +100、正常消息 −1，**累计到 1000 电机退出使能**。
   频繁触发说明控制参数或姿态有问题，不要靠重启硬扛。
5. **所有新控制程序先在 MuJoCo 仿真验证，再上真机**；异常时**先按急停**。
6. **不要在真机上同时用两个程序控制同一只手 / 同一台机器人**（包括官方上位机和脚本）。
7. **改完 `ROS_DOMAIN_ID` 相关的服务配置记得 `daemon-reload`**，否则重启也不生效。

## 9. 与灵巧手这一侧的衔接

灵巧手（Revo2）在整机上走的是 **CANFD**，通过 `/canfd_packet/rx` 和 `/canfd_packet/tx`
与机器人硬件节点通信 —— 也就是说，**灵巧手不是接在机器人本体总线上，
而是接在主控板的 CAN5（左手）/ CAN6（右手）这两条独立接口上**。

官方给灵巧手的接入说明与示例：

| 内容 | 位置 |
|---|---|
| 官方接入文档 | `BXI_Wiki/docs/elf3/developer/dexterous_hand.zh.md` |
| 官方示例仓库 | `github.com/konodoki/bxi_revo2_example`（64 KB，含 C++/Python 两个示例） |
| Python SDK | `pip install bc-stark-sdk==1.5.1` |
| C++ SDK | 在示例仓库里跑 `./download-lib.sh` |

官方示例里的默认配置（与我们的台账一致，本项目用右手那行）：

```python
right_ctx = await init_bxipci_device(6, 127, master_id=1, is_canfd=True, ...)  # 右手 CAN6 / ID 127 ← 本项目
left_ctx  = await init_bxipci_device(5, 126, master_id=1, is_canfd=True, ...)  # 左手 CAN5 / ID 126（备选）
```

**和本目录自有代码的关系**：

- 本目录 `src/elf3_ros2/revo2_bridge_node.py` 是**我们按协议手写的桥接节点**；
- 官方 `bxi_revo2_example` 是**厂商实现**，遇到分歧以官方为准；
- 两边可以先各跑一次，用同一个 `/canfd_packet` 链路交叉验证，再决定用谁的。

> 灵巧手侧的详细流程见
> [`09-装配到机器人后的首次整机联调.md`](09-装配到机器人后的首次整机联调.md)
> 与 [`04-通信协议速查-Modbus与CANFD.md`](04-通信协议速查-Modbus与CANFD.md)。

## 10. 故障速查（真机侧）

| 症状 | 先查这个 |
|---|---|
| 话题列表是空的 | `ROS_DOMAIN_ID` 和硬件节点不一致（§2.2）；或者在普通用户 shell 里而非 root shell |
| `ros2 launch` 找不到包 | 忘了 `source`，三条都要 |
| `communication/msg/MotionCommands not found` | 没 source `/opt/bxi/bxi_ros2_pkg/setup.bash` |
| 发了指令机器人不动 | ① 是否先发了「初始姿态」② `ROS_DOMAIN_ID` ③ 是不是发了仿真话题前缀 |
| 动到一半瘫软 | 100 ms 失控保护触发，重新初始化（见 §8.2/8.3） |
| 灵巧手不响应 / 读超时 | ① 左手 CAN5 且 ID 126、右手 CAN6 且 ID 127 ② `/canfd_packet/rx`、`/canfd_packet/tx` 是否存在 ③ 线缆与供电 ④ 是否有别的程序在控同一只手 ⑤ `ROS_DOMAIN_ID` 是否一致 |
| 编译不过 | 先 `ls src/bxi_example_py_elf3/launch/` 确认真实文件名 |
| 服务改了配置不生效 | `sudo systemctl daemon-reload` |
