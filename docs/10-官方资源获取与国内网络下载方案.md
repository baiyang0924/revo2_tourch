# 10 · 官方资源获取与国内网络下载方案

> **适用对象**：需要在本机 / 机载电脑 / 开发板上装半醒（BXI）与强脑（BrainCo）官方库的人
> **文档状态**：v1.0（2026-09-20）
> **实测环境**：Windows 11 笔记本（本机），`curl` / `git` 可用
>
> **一句话结论**：
> 大部分"官方库下不下来"不是网络封锁，而是**方式选错了**——
> `bxi_controller_ros2` 直接 `git clone` 要拉 **425 MB**，
> 而官方同时提供 **63 MB 的预编译发布包**；
> 真实的网络卡点只有两个：`release-assets.githubusercontent.com`（国内常 502）
> 和 GitHub 大仓库断流。另有**一条 0 下载的路线**：局域网从机器人或同事机器直接拷。

---

## 0. 先分清你要的是哪个"官方库"

这是最容易混的地方 —— 手上这套设备牵扯**两家厂商**的库：

| 厂商 | 产品 | 库的形态 | 你要不要 |
|---|---|---|---|
| **半醒 BXI** | ELF3 人形机器人 | GitHub 上的 ROS 2 包 + 控制策略仓库 | 整机联调 / 仿真要 |
| **强脑 BrainCo** | Revo2 灵巧手 | PyPI 的 Python SDK + 官网 CDN 的 C++ SDK | 灵巧手桌面调试要 |

两者互不相干，装错方向会白折腾。

## 1. 官方资源总清单（含实测体积）

## 2. 三条下载路线

**按这个顺序试，路线 A 不需要任何外网。**

### 路线 A · 局域网直拷（0 下载，最快最稳）

机器人机载电脑上**本来就有全套环境**，同事的开发机上也已经编译好了。
与其在公网上跟 425 MB 较劲，不如把已经下好的东西拿过来。

**A-1 从机器人上拉（机器人在线时首选）**

```bash
# 在你的 Linux 机上执行；Windows 客户端同样支持 scp
mkdir -p ~/elf3_ws /tmp/bxi_pull
scp -r bxi@elf3-82.local:/opt/bxi/bxi_ros2_pkg            /opt/bxi/bxi_ros2_pkg
scp -r bxi@elf3-82.local:/home/bxi/bxi_ws/bxi_rl_controller_ros2_example  ~/elf3_ws/
```

> `/opt/bxi/bxi_ros2_pkg` 里**已含编译好的二进制**，拷过来 `source setup.bash` 就能用，
> 省掉 `colcon build`。

**A-2 从同事的开发机上拉（用 `git bundle`，保留完整提交历史）**

```bash
# —— 在同事那台机器上 ——
cd ~/elf3_ws/bxi_rl_controller_ros2_example
git bundle create ~/bxi_ctrl.bundle --all
# 把 bxi_ctrl.bundle 拷给你（U 盘 / 局域网 / 微信文件传输均可）

# —— 在你的机器上 ——
git clone ~/bxi_ctrl.bundle bxi_rl_controller_ros2_example
git remote set-url origin https://github.com/bxirobotics/bxi_controller_ros2.git
```

**A-3 只要源码、不要历史（tar 直传）**

```bash
# 同事机器上
tar czf ~/bxi_ctrl_src.tar.gz --exclude=.git --exclude=build --exclude=install --exclude=log \
    -C ~/elf3_ws bxi_rl_controller_ros2_example
# 自己机器上
tar xzf bxi_ctrl_src.tar.gz -C ~/elf3_ws
```

### 路线 B · 只下必需的两个东西（约 160 MB，绕过 425 MB 大仓库）

```bash
# ① 预编译发布包：先看有哪些版本
#    浏览器打开 https://github.com/bxirobotics/bxi_controller_ros2/releases
#    取最新 tag（例如 v260920）的 amd64 包
TAG=v260920
curl -L -O "https://github.com/bxirobotics/bxi_controller_ros2/releases/download/${TAG}/bxi_rl_controller_ros2_example_${TAG}_amd64.tar.gz"
curl -L -O "https://github.com/bxirobotics/bxi_controller_ros2/releases/download/${TAG}/bxi_rl_controller_ros2_example_${TAG}_amd64.tar.gz.sha256"

# ② 二进制 ROS 2 包（浅克隆，不拉历史）
sudo mkdir -p /opt/bxi && cd /opt/bxi
sudo git clone --depth 1 https://github.com/bxirobotics/bxi_ros2_pkg.git
```

**如果只有源码包、没有预编译包**，就给大仓库加浅克隆：

```bash
git clone --depth 1 https://github.com/bxirobotics/bxi_controller_ros2.git
# 或再狠一点，连 blob 都按需拉
git clone --depth 1 --filter=blob:none --no-checkout \
  https://github.com/bxirobotics/bxi_controller_ros2.git
```

> `--depth 1` 只取最近一次提交的快照，是**断流场景下最有效的一招**：
> 425 MB 里有很大一部分是历史版本里的 ONNX 模型。

### 路线 C · 国内加速前缀（走公网时的兜底）

**本机 2026-09-20 实测结论：**

| 加速前缀 | 实测 |
|---|---|
| 直连（无前缀） | 响应正常，**但下载大文件会被重定向到 `release-assets.githubusercontent.com`，实测返回 `502 Bad Gateway`** |
| `https://ghfast.top/` | ✅ 可达（HTTP 206） |
| `https://gh-proxy.com/` | ✅ 可达（HTTP 206） |
| `https://ghproxy.net/` | ✅ 可达（HTTP 206） |
| `https://github.moeyy.xyz/` | ❌ 不通 |
| `https://hub.gitmirror.com/` | ❌ 不通 |

用起来就是把原地址整段拼在前缀后面：

```bash
curl -L -O "https://ghfast.top/https://github.com/bxirobotics/bxi_ros2_pkg/archive/refs/heads/main.tar.gz"
```

或者给 `git` 全局配一次（只影响 `github.com`，别的影响不到）：

```bash
git config --global url."https://ghfast.top/https://github.com/".insteadOf "https://github.com/"
# 想撤销：
git config --global --unset url."https://ghfast.top/https://github.com/".insteadOf
```

### 路线 D · 灵巧手 SDK（不用绕，国内本来就快）

```bash
# Python 端（官方指定版本 1.5.1；Windows 笔记本同样适用）
pip install bc-stark-sdk==1.5.1 -i https://pypi.tuna.tsinghua.edu.cn/simple

# C++ 端（官方 download-lib.sh 的内部实现，国内 CDN）
#   linux / win / linux-arm64 / mac 四选一
curl -L -O https://app.brainco.cn/universal/bc-stark-sdk/libs/v1.4.2/linux.zip
```

用官方脚本时它会自己拼这个地址：

```bash
cd bxi_revo2_example && ./download-lib.sh
```

## 3. "一直下不成功"的原因对照表

| 你看到的现象 | 真实原因 | 怎么办 |
|---|---|---|
| `git clone` 停在 `Receiving objects: xx%` 然后报 `fetch-pack: invalid index-pack output` / `early EOF` | 425 MB 大仓库 + 断流。**不是你的错，也不是文件坏了** | 换路线 B 的预编译包；必须克隆就加 `--depth 1` |
| 浏览器/curl 下 release 包进度一直是 0，或直接 `502 Bad Gateway` | GitHub 把资产重定向到 `release-assets.githubusercontent.com`，**这个域名国内经常不通**（本机实测确实 502） | 换路线 A（局域网拷）或路线 C（加速前缀） |
| `pip install bc-stark-sdk` 超时 / 找不到 | 直连 `pypi.org` 不稳 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 装完了仍然 `No module named bc_stark_sdk` | 装进了**另一个 Python 环境**（系统 Python / conda / venv 混了） | 用同一个解释器装和跑：`python -m pip install ...`，并确认 `python -c "import sys;print(sys.executable)"` |
| 编译报缺少 `stark-sdk.h` / `libbc_stark_sdk.so` | 没跑 `./download-lib.sh`，缺 `dist/` 目录 | 进 `bxi_revo2_example` 跑 `./download-lib.sh`，再 `colcon build` |
| 官方 Wiki 页面打不开 | Wiki 是仓库里的 mkdocs 源码，不是现成网站 | 直接读仓库里的 `.md`，或用 `mkdocs serve` 本地起 |
| 仓库名 `bxi_rl_controller_ros2_example` 克隆报 301 / 找不到 | 仓库已改名，旧名会跳转到 `bxi_controller_ros2` | 用新名；`git` 会自动跟随跳转 |

## 4. 下载后必须做的两件事

**① 校验完整性**（官方每个发布包都配了 `.sha256`，就是给这件事用的）

```bash
sha256sum -c bxi_rl_controller_ros2_example_v260920_amd64.tar.gz.sha256
# 输出 "...OK" 才算下完；失败就重下，别凑合解压
```

**② 记下版本号**（本仓库的台账习惯）

把实际用的 tag 填进 `config/hand_params.yaml` 或 `CHANGELOG.md` ——
以后出现"同事那边正常、我这边不正常"，第一件事就是比对版本号。

## 5. 那台笔记本到底要不要装这一整套？

**先说结论：为了"机器人整机联调"，不需要。**

| 你想做的事 | 笔记本要装什么 |
|---|---|
| SSH 进机器人跑现成的 launch | **什么都不用装**，Windows 自带 `ssh` 就够 |
| 在笔记本上**自己发 ROS 2 话题**控制机器人 | 要 Ubuntu 22.04 + ROS 2 Humble |
| 在笔记本上录 `ros2 bag` / 调 DDS | 同上 |
| 在笔记本上跑 MuJoCo 仿真 | 同上，且**显卡要够**（仿真吃 GPU） |
| 只是先把整机链路跑通、验证一下 | **什么都不用装** |

判断依据只有一条：**你需不需要"在笔记本上"做一个 ROS 2 节点。**

- `revo2_bridge_node.py` 这类要直接占 CAN 链路的节点，**永远只能跑在机器人上**
  （PCIe→CANFD 板卡在机器人肚子里），装不装双系统都一样。
- 如果你的笔记本没有独立显卡，MuJoCo 仿真体验会很差，
  这时候**用同事那台 14900K + 4090 更划算**（那台就是为仿真配的）。

> **实操建议**：先用"SSH + 从机器人拷"把整机链路跑通；
> 等真的需要在本机开发 ROS 2 代码或跑仿真时，再按
> `docs/reference/` 里那份装机方案装系统，不要为了"装而装"。
